# Качество GeoTrace 0.8 beta 1

Сравнение выполнено 21 ноября 2026 с опубликованной 0.3.0 alpha 1. Это небольшой прирост точности положения контактов, а не устранение всех артефактов. **Цель среднего IoU 0,90 не достигнута.** F1 границ и IoU полигонов измеряют разные свойства; F1 выше 0,90 не означает достигнутую точность полигонов.

## Изменение алгоритма

В подробном уточнении усилен ограниченный голос цвета открытой бумаги соседей: 0,20 → 0,35. Защита чернил, недостаточно надёжных моделей, узких связей, отверстий и узлов сохранена. Настройки пользователя не добавлялись. Расширение полосы уточнения с 1,5 до 2,5 масштаба не включено: дополнительный выигрыш был слишком мал. Поиск линий в 16 направлениях также отклонён: на Apache Gap он дал больше фрагментов и снизил IoU, хотя F1 вырос. Ослабление порогов объединения по бумаге не дало улучшения и не вошло в выпуск.

Имена карт, эталонные координаты и ID объектов в алгоритм не добавлялись. Apache Gap использован для выбора изменения; Caballo оставлен внешней проверкой. После проверки Caballo параметры повторно не подбирались. Российский фрагмент уже использовался в разработке и не является независимым внешним тестом.

## Измерения

| Карта | Средний IoU: 0.3 → 0.8 | F1 границ: 0.3 → 0.8 |
| --- | --- | --- |
| Известный российский фрагмент | 0.805602 → 0.805747 | 0.850802 → 0.851111 |
| Apache Gap | 0.622398 → 0.622647 | 0.934497 → 0.934592 |
| Caballo | 0.590068 → 0.590303 | 0.923489 → 0.923623 |

Методика: каждому эталонному объекту площадью от 256 рабочих пикселей сопоставляется один предсказанный полигон с максимальным IoU. Среднее невзвешенное по объектам; это не однозначное взаимное назначение объектов. Неразмеченные пиксели исключаются. F1 вычисляется по границам с допуском 3 рабочих пикселя внутри маски, с отступом 4 пикселя от её края. На российском фрагменте оценивается 71 объект, Apache Gap — 531, Caballo — 353. Метрики в таблице используют одинаковые декодированные растр и маску до/после; старые результаты нестабильного VRT-декодера не подмешивались.

Растры и векторы внешних карт могут относиться к разным редакциям. Эталон не является безошибочной разметкой каждого штриха печати. Результаты не переносятся автоматически на произвольные карты и не измеряют правильность геологических названий.

В Caballo количество полигонов меньше 80 рабочих пикселей выросло с 599 до 601 при том же общем количестве: небольшой рост IoU не означает уменьшение всех мелких артефактов.

На всех десяти вариантах проверены валидность геометрии, полное покрытие допустимой маски и отсутствие наложений. На семи российских вариантах также проверена неизменность входных массивов. На полном листе с проблемной печатью отдельно проверены сохранность ручного защищённого объекта и сохранение/открытие проекта. Два обрезанных листа дали полностью прежние геометрию и атрибуты: новое уточнение не обязано срабатывать без более подробных исходных данных.

Локальный pytest: **314 passed** на macOS. Дополнительный запуск настоящего QML-интерфейса проверяет подготовку, предпросмотр, отметку сомнения, применение, сохранение/открытие, отмену и справку F1. Автоматические проверки Windows/macOS и итоговый номер build смотрите в Checks, указанном в метаданных опубликованного архива; успешный локальный pytest не означает успешный CI.

## Воспроизведение

Установите зависимости разработки и запустите текущий метод на своей карте:

```sh
python tools/benchmark_quality.py --raster map.tif --output report.json
python tools/benchmark_quality.py --raster map.tif --reference reference.npy --output scored.json
```

`reference.npy` — заранее независимо подготовленный целочисленный массив идентификаторов в **рабочей** сетке `read_raster`, где 0 означает отсутствие эталона. Совпадения размера недостаточно: систему координат, transform и фактическое совмещение нужно проверить при растрировании векторов. Эталон загружается для оценки и не передаётся в сегментацию. Инструмент сохраняет версию, размер, число полигонов, проверки покрытия, IoU по объектам и F1. Без эталона он проверяет только геометрию, не семантическое качество. Исторический `benchmark_auto.py` оценивает дополнительные старые методы и не воспроизводит основной метод 0.8.

Для честного сравнения используйте те же файлы, маски, рабочую сетку и версии библиотек, фиксируйте SHA-256 исходников. Приватные карты и эталоны пользователя не включены в репозиторий. Внешние источники: [Geologic Map 74, Caballo / Apache Gap](https://geoinfo.nmt.edu/publications/maps/geologic/gm/74/), [Picture Rock, OF-GM 51](https://geoinfo.nmt.edu/publications/maps/geologic/ofgm/details.cfml?Volume=51). Источники и более ранние эксперименты подробно записаны в [VALIDATION.md](../VALIDATION.md).

## Оставшиеся проблемы

Близкие заливки, подписи поверх тонких контактов, плотная штриховка и мелкие линзы всё ещё могут давать лишние либо пропущенные полигоны. Ограничение разрешения теряет детали. Общие геологические индексы не распознаются автоматически. Улучшение среднего значения не гарантирует улучшение каждого отдельного объекта. Для существенного следующего прироста нужны дополнительные независимые размеченные карты и оценка затрат ручной правки, а не только очередное изменение порога.
