# Проверка GeoTrace 1.0

## Что изменилось

Версия 1.0 расширяет проект до нескольких исходных листов и общего участка, вводит отдельные линейные объекты, геодезические измерения, оформление и макеты. Основной метод полигональной сегментации версии 0.8 сохранён. Новые проверки не являются новой оценкой среднего IoU. Цель 0,90 остаётся недостигнутой; исторические метрики и методика приведены в [QUALITY.md](QUALITY.md).

## Реальный проект двух листов

24 ноября 2026 обработаны полные O-48-XI и O-48-XVII с предоставленным KML. Исходники: 2533×1689 и 2531×1687 пикселей. Распознавание выполнялось по каждому полному листу, а KML применялся к общей геометрии в EPSG:3857.

| Проверка | Наблюдение |
| --- | --- |
| Полные листы | 886 и 1006 полигонов; совпадает с ранее проверенными количествами 0.8 |
| Общий участок | 125 полигонов, 11 исходных классов до ручного сопоставления |
| Время расчёта и сборки | 52,855 секунды на рабочем Mac в текущем окружении |
| Геометрия | Все выходные полигоны корректны |
| Перекрытия | Относительная разность суммы площадей и объединения −1,62×10⁻¹⁵, в пределах машинной погрешности |
| Проект | Сохранён и повторно открыт, оба листа сохранены |
| Экспорт | GeoPackage и PDF записаны; предпросмотр макета проверен визуально |

Время не включает проверку специалистом и не является измерением экономии относительно ручной оцифровки. Отсутствие наложений не доказывает правильность геологических контактов.

## Проверяемые свойства

- Совмещение двух листов с разными цветами и общими классами; отсутствие двойной площади в перекрытии.
- Сохранение точной ручной геометрии при изменении сетки обзорного изображения, перенос проекта и миграция старого формата.
- Площадь с отверстиями и длина на WGS84; отдельно проверено существенное отличие от искажённых площадей Меркатора на 60° широты.
- Скелет линий с ветвлениями и замкнутыми контурами, исключение широкой заливки, соединение с обоих концов, изменение вершин и разделение.
- Сохранение одной линии одним объектом MultiLineString после разрезания KML; физическая длина считается по всем частям.
- Ограниченное чтение исходного окна при приближении; изменившийся TIFF не подменяет встроенный снимок проекта. Маска рамки сохраняется; NoData не должен давать тёмный ореол.
- Полная легенда без потери длинных названий, дополнительные страницы, проверка рамок макета, атлас без повторной общей страницы.
- Настоящий QML-интерфейс: макет в рабочем процессе, экспорт в отдельном worker-процессе, продолжение линий, блокировка слоя.
- Существующие проверки оцифровки, ручных границ, атрибутов, подложек, сохранения и браузерной вкладки.

Полный локальный запуск после доработки интерфейса: 332 проверки прошли за 72,09 секунды. Дополнительно проверены выбор групп A/B кликами на карте, сшивка двух полигонов в один, восстановление подсветки при отмене переноса вершины, возврат статуса после автосохранения, настоящие события жестов тачпада, удержание точки масштаба и доступность панели атрибутов линий. Компоновка макета проверяется по реальным размерам панели и предпросмотра. Число успешных проверок Windows/macOS и номер финального build берутся из фактического запуска CI.

## Автономная сборка

`tools/smoke_frozen.py` запускает реальный исполняемый файл из временной папки с удалёнными настройками Python-окружения. Программа создаёт два временных TIFF, запускает распознавание в собственном worker-процессе, применяет результат, рисует линию, сохраняет переносимый проект, повторно открывает его и экспортирует GeoPackage и PDF. Затем проверяет загрузку локальной страницы через встроенный браузер без обращения к внешнему API.

Проверка выполняется до упаковки и из установленного приложения в среде CI. Отчёты `selfcheck-*` и `installed-*` содержат версии библиотек и результат. Эта проверка не подтверждает доступ конкретного ключа Яндекса и не заменяет испытание на всех пользовательских компьютерах. Для данного Mac-пакета нижняя граница 14.4 обусловлена включённым Qt; это проверяется по нативным библиотекам, а не по одной надписи в установщике.

## Оставшиеся ограничения

Качество сложной печати и семантических соответствий требует ручной проверки. Цветной или чёрный штрих сам по себе не устанавливает наличие разлома; прерывистые структуры часто нужно продолжать вручную. Геологические названия не распознаются автоматически. Обзорная сетка ограничена 1600 пикселями по длинной стороне, подробный анализ — 12 млн пикселей на лист, растровая часть страницы — 24 млн пикселей. Векторные контуры выводятся отдельно от растра.

Для дальнейшей количественной оценки нужны независимая разметка новых листов, отложенный набор и замер времени проверки/правки. Небольшой технический пример не обосновывает универсальную точность или фиксированный процент экономии времени.
