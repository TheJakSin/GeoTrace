# Версии и выпуск GeoTrace

## Версия и номер сборки

Текущая версия — **0.8 beta 1**, тег **v0.8.0-beta.1**, версия Python-пакета **0.8.0b1**. Переход с 0.3 alpha на 0.8 beta обозначает выбранный этап продукта, а не пять выпущенных промежуточных версий. Номер формата проекта независим от версии приложения.

**Build** равен `run_number` процесса GitHub Actions **Checks**. Один запуск с двумя платформами считается одной сборкой. Неудачный запуск также занимает номер; повторная попытка того же запуска сохраняет номер, но получает другой attempt. В истории перед этим выпуском было шесть запусков; №5 и №6 проверяли один коммит (второй был вызван тегом). Следующий запуск main начинает с №7. Финальным номером выпуска считается фактический успешный запуск, а не заранее обещанное число.

С этого выпуска push-проверки ограничены веткой main, чтобы создание тега не запускало вторую сборку того же кода. Проверки PR и ручной запуск остаются доступны и также занимают номера. Считать число локальных коммитов, диалогов или изменений алгоритма номером build нельзя.

В пакетах `src/geotrace/build_info.json` содержит версию, номер, полный SHA исходного коммита, адрес запуска Checks и время упаковки UTC. Метаданные создаются после тестов перед упаковкой; в Git этот файл не хранится. При отсутствии, повреждении или несоответствии версии приложение показывает **dev**. Изменяя исходники после распаковки официального архива, удалите этот файл, иначе метка перестанет описывать изменённый код.

## Проверки перед публикацией

1. Обновить `pyproject.toml` и `src/geotrace/__init__.py`, changelog и документацию.
2. Выполнить полный pytest, проверить настоящий QML-интерфейс и регрессию карт. При изменении качества сравнить с предыдущим выпуском на тех же пикселях/масках; не менять одновременно декодер и алгоритм без отдельного сравнения.
3. Опубликовать исходники в main и дождаться успешных Windows/macOS jobs одного и того же SHA в Checks.
4. Взять фактические номер и URL этого запуска, создать метаданные и собрать wheel/sdist. При ручной упаковке источник должен иметь то же дерево файлов, что проверенный удалённый коммит.
5. Проверить состав архивов, версии, метаданные, ресурсы QML/HTML/SVG/PNG, документацию, отсутствие карт, проектов, весов, `.venv` и временных данных.
6. Создать архив запуска и SHA256SUMS. Для source ZIP, полученного через `git archive`, явно включить сгенерированный `build_info.json`: игнорируемый файл автоматически туда не попадёт.
7. Создать prerelease с тегом проверенного SHA, приложить файлы и после загрузки проверить их SHA-256. Сверить тег, SHA и успешный Checks; сохранить сведения о публикации.

Команды для окружения Python 3.11:

```sh
python -m pip install -e ".[dev]"
python -m pytest -q
python tools/write_build_info.py --number NUMBER --commit FULL_SHA --run-url RUN_URL
python -m build
```

Вместо NUMBER, FULL_SHA и RUN_URL подставляются значения проверенного Checks. Команда не вычисляет build по локальному Git и не публикует ничего самостоятельно. При обычной разработке метаданные генерировать не требуется.

## Состав выпуска

| Файл | Назначение |
| --- | --- |
| `GeoTrace-0.8.0-beta.1-buildN.zip` | Основной архив: исходники, документация, сценарии запуска, метаданные build |
| `geotrace_desktop-0.8.0b1-py3-none-any.whl` | Установка через pip, требует Python и зависимостей |
| `geotrace_desktop-0.8.0b1.tar.gz` | Исходный Python-пакет с документацией и метаданными |
| `SHA256SUMS.txt` | Контрольные суммы трёх файлов |

Автоматические ссылки GitHub **Source code** содержат дерево тега без сгенерированной метки build; при запуске это dev-исходники. Для маркированного выпуска используйте приложенный архив GeoTrace. Wheel и ZIP не являются автономными Windows/macOS установщиками. Успешный CI подтверждает тесты и сборку на runner, но не испытание интерфейса на любом реальном оборудовании.
