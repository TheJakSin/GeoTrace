# GeoTrace 1.0

Приложение для оцифровки геопривязанных карт: проект участка с несколькими листами, полигоны и линии, проверка результата, атрибуты и выпуск оформленной карты.

## Установка

Готовые приложения и установщики находятся в [GitHub Releases](https://github.com/TheJakSin/GeoTrace/releases/latest). Python устанавливать не нужно.

- **Windows x64** — мастер `*-Windows-x64-Setup.exe` или ZIP с папкой программы.
- **Mac Apple Silicon** — `*-macOS-arm64.pkg` либо ZIP с `.app`.
- **Mac Intel** — `*-macOS-x86_64.pkg` либо ZIP с `.app`.

Для Mac-сборки с Qt 6.12 нужна macOS 14.4+. Windows — 64-разрядная Windows 10/11. Основной алгоритм работает на CPU. Установщики не подписаны платным сертификатом издателя; возможны системные предупреждения. Проверяйте источник и SHA-256 из выпуска. Номер build — номер проверенного запуска Checks, он записан в приложение и отчёты самопроверки.

## Основной сценарий

1. Добавьте участок KML и полные геопривязанные TIFF.
2. Выберите лист, проверьте рамку и палитру, при необходимости разделите оттенки пипеткой.
3. Рассчитайте и примените предпросмотр; для нескольких листов используйте общую очередь.
4. Сопоставьте группы разных цветов общим классам, проверьте стыки и сомнительные участки.
5. Исправьте границы, добавьте линии, заполните атрибуты.
6. Сохраните проект, экспортируйте GeoPackage либо карту и атлас через макет.

В окне используется EPSG:3857. Площади и длины вычисляются геодезически на WGS84; плоская площадь Меркатора не выдаётся за физическую. Исходные файлы не переписываются. Для переноса на другой компьютер можно сохранить проект вместе с исходниками.

## Разработка

Нужен Python 3.11. Сценарии `Start GeoTrace.command` и `Start GeoTrace.bat` предназначены для запуска исходников, а не для установки готового приложения.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m geotrace.launcher
.venv/bin/python -m pytest -q
```

В Windows используйте `.venv\Scripts\python.exe`. Обычная работа не требует нейросетевых весов. Исследовательские зависимости устанавливаются отдельно и не входят в штатную автономную сборку. Карты пользователя, эталоны, рабочие проекты и личные ключи в Git не включаются.
