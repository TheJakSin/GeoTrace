# Направление разработки

## Согласованный продукт

- Первая версия предназначена для геологии; позже возможны другие тематические карты.
- Входная карта уже географически привязана.
- Основной сценарий: автоматическое построение → проверка → локальная ручная коррекция.
- Полностью ручная оцифровка нужна как дополнительный режим.
- Геометрия является основой; набор атрибутов настраивается для каждой задачи.
- Windows имеет приоритет, macOS желательна. Для начала разработки переход на Windows не требуется.
- Красивый, удобный интерфейс, отзывчивость, сохранность правок и история версий являются требованиями.

## Архитектура текущего эксперимента

`core.py` не зависит от интерфейса: чтение растра, классификация, геометрия, экспорт.
`app.py` управляет состоянием и отдельным процессом обработки.
`qml/Main.qml` содержит интерфейс просмотра и редактирования базовых атрибутов.
`editing.py` выполняет векторные правки пары/одного объекта с проверкой сохранения покрытия.
Растровые метки служат кэшем заливки; линии отрисовываются по геометрии, включая границы объектов одной группы.
Автоматические предложения остаются пиксельными; пересечение с защищёнными объектами проверяется по вектору.

Не привязывать геологические классы к постоянным числам кластеров: в текущем алгоритме номера
локальны для запуска и не имеют предметного значения. В будущем распознавание должно возвращать
предложения с происхождением и основанием для проверки, а правки пользователя храниться отдельно.

## Следующие этапы

1. Подготовить небольшие согласованные эталонные фрагменты: чистая заливка, штриховка,
   подписи поверх границ, разломы и близкие цвета. Проверить соответствие готового примера исходнику.
   Измерять не только совпадение областей и границ, но и время ручной доводки.
2. Сравнить улучшенную обработку изображения и интерактивную сегментацию.
   Добавить положительные/отрицательные подсказки, локальный пересчёт и защиту подтверждённых правок.
3. Проекты, восстановление, объединение/разделение и замена общей границы реализованы локально.
   Добавлены ручные новые полигоны и перемещение общих вершин. Далее — привязка, добавление/удаление вершин и история между сеансами.
4. Конструктор дополнительных полей реализован: текст, числа, дата, логическое значение,
   списки, обязательность и значения по умолчанию. Таблица и массовое заполнение добавлены. Далее — шаблоны и справочники классов.
5. Испытать на реальном Windows-ПК, настроить установщики и выпуск версий через GitHub Releases.

Геометрию и геологическую семантику проверять отдельно. Отсутствие геометрических ошибок не означает
правильную оцифровку. Не использовать число полигонов как показатель качества.

## Открытые вопросы

- Типичные размеры карт; характеристики Windows-ПК уже известны.
- Допустимое отклонение границы с учётом масштаба и качества скана.
- Правила выделения одинаковых подразделений, разделённых разломом; какие линии и точки нужны отдельно.
- Формат распространения программы и установщиков. Приватный репозиторий создан:
  https://github.com/TheJakSin/GeoTrace .

## Требования к ресурсам и состояние на 13 ноября 2026

Windows-ПК пользователя: Intel Core i7-13700K, 32 ГБ ОЗУ, RTX 4070 Ti. Это машина для
разработки/проверки Windows, но не целевой минимум. Приложение должно оставаться полезным
на более слабом оборудовании. Предварительные цели: 4 ядра / 8 ГБ / встроенная графика для
базовой работы и локальных операций; 16 ГБ — основной ориентир. Цели ещё не подтверждены.

В 0.2 вычисления выполняет один рабочий процесс; OpenCV и PyTorch ограничены двумя потоками.
Рамка подсказок ограничена 768 × 768 рабочими пикселями. Модель загружается по запросу,
кэшируется только последнее закодированное окно. Нейросеть не обязательна. GPU ещё не подключён.

Этапы 1–2 выполнены как диагностический эксперимент: проверено совмещение примера,
подготовлены четыре фиксированных окна, сравнены цветовой метод и MobileSAM.
Подсказки +/−, принятие, защита принятых/редактированных объектов и отмена доступны в интерфейсе.
Качество на сложных областях остаётся недостаточным; результаты приведены в EVALUATION.md.

Следующий приоритет: согласовать целевые границы на сложных фрагментах, улучшить обработку
штриховки/линий; продолжить редактор геометрии и настройку атрибутов поверх сохранения проектов.
История действий ограничена последними 12 операциями. Отмены выполняющегося задания пока нет.

Код 0.2 опубликован в приватном репозитории. Проверки GitHub Actions на Windows и macOS
прошли успешно: по 15 тестов, сборка wheel и архива исходников; подробности в VALIDATION.md.

## Локальный этап: сохранность работы

Добавлен переносимый `.geotrace`: рабочий растр, привязка, полигоны, применённые атрибуты,
подсказки. Сохранение атомарное; копия восстановления обновляется в свободное время.
Открытие не требует наличия исходного TIFF. История отмены между запусками пока не сохраняется.
Добавлены объединение, разделение линией и замена общей границы с предпросмотром и отменой.

По просьбе пользователя промежуточные изменения не публикуются автоматически. Проверять
затронутые сценарии; полные проверки и GitHub-публикации — на значимых этапах.

## Ручная геометрия

`editing.py`: операции в рабочих координатах пикселей, возврат в исходную CRS без растеризации
самой геометрии. Неподвижные соседи сохраняются точно; покрытие выбранного множества проверяется
по площади симметрической разности и наложений. Предпросмотр работает в отдельном процессе.
Объединение сохраняет атрибуты первого объекта, разделение наследует их обеим частям,
замена общей границы сопоставляет стороны по площади пересечения. Предпросмотр и линия временные.
Для геологической проверки качества границ по-прежнему нужны согласованные эталонные участки.

## Рисование и перемещение вершин

Новый полигон создаётся без предварительной сегментации, только в свободной валидной части карты.
Общая вершина перемещается во всех примыкающих кольцах с согласованными промежуточными узлами
на рёбрах; проверяется ожидаемое покрытие после деформации внешнего контура и отсутствие наложений.
Ручной инструмент не стирает соседние объекты. Поле маркеров ограничено размером viewport
при любом масштабе. Конструктор атрибутов, таблица и массовое заполнение добавлены; далее — шаблоны и справочники классов.

## Настраиваемые поля

`Result.fields` хранит схему, `attributes.py` валидирует типы и атомарно подготавливает
изменение схемы. Все операции создания/редактирования геометрии сохраняют схему и наследуют
значения либо применяют defaults для новых объектов. Проект v2 хранит схему; чтение v1 сохранено.
Экспорт проверяет обязательность до создания файла, сохраняет типы колонок; логические значения
передаются как nullable 1/0. Изменения схемы входят в общую историю отмены.
Модель динамических полей QML обновляется только при изменении схемы, чтобы статусные уведомления
и автосохранение не пересоздавали редакторы и не стирали неприменённый ввод.

## Таблица и массовые операции

`table.py`: QAbstractTableModel с фильтром, типизированной сортировкой и выбором по object_id.
Поисковые строки кэшируются до изменения атрибутов/геометрии. QML TableView переиспользует
видимые ячейки; данные выбранных строк не зависят от позиции после сортировки.
Массовая операция сначала готовит неизменяющий данные план; применение проверяет ревизию.
История хранит старые свойства изменённых объектов, не дублируя геометрию. Один шаг отмены
восстанавливает всю массовую операцию. Фильтры и выбор являются состоянием интерфейса.
Живой пользовательский сеанс проверки на Mac отложен по доступности пользователя;
разработка продолжается с локальными целевыми проверками и снимками интерфейса.

## Автоматическое выделение с сохранением правок

`preprocessing.py` содержит общий для подсказок и профиля scan CPU-фильтр печати.
`core.segment(..., profile='baseline'|'scan')` по умолчанию сохраняет прежний алгоритм.
Скан использует локальную оценку яркости, inpaint, median 5 и вес L=0.4 в Lab;
при формировании палитры вес яркости снимается. Классы являются цветовыми группами.

`automatic.preserve_work` сохраняет защищённые векторные геометрии точно, обрезает
новые по их объединению, проверяет покрытие и наложения. Labels пересчитываются только
как кэш заливки. Свободные номера палитры переиспользуются; защищённые class_id стабильны.
Объекты с заполненными базовыми атрибутами или отличающимися от defaults значениями также защищены.
`auto_job` выполняется в существующем отдельном процессе. UI хранит предпросмотр
с ревизией исходных данных, до применения результат не сохраняется. Изменение данных
сбрасывает предпросмотр; принятие добавляет один снимок в историю отмены.
CLI `--auto` оставлен без предпросмотра для разработческих проверок обычного алгоритма,
но повторный запуск также сохраняет защищённые объекты и доступен для отмены.

Протокол сравнения и ограничения: AUTO_EVALUATION.md. Не переносить результаты одного
листа на другие карты; режим scan оставлен опциональным из-за регрессий отдельных объектов.
