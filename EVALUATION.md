# Диагностика распознавания · 13 ноября 2026

## Материалы и ограничения сравнения

Использованы `Пример/Растр/Геологическая карта_clip_cut_buffer800.tif` и
`Пример/Вектор/gpkg/geolmap_edit.gpkg` из переданной пользователем папки.
Наложение границ визуально согласуется с изображением; это не подтверждение геологической
правильности готовой оцифровки. В таблице 76 записей, одна имеет пустую геометрию.
Пустая геометрия исключена из диагностического набора. Все непустые геометрии проходят
проверку валидности. По краю есть небольшие несовпадения растра и вектора.

Рабочий растр — 1600 × 963 px. Из него выбраны четыре окна 512 × 512 px:
по одному для крупнейшего объекта классов O2kr1, O2-3mk, Cm3il и Q_IV. Окно центрируется
на внутренней точке целевого объекта с учётом границ растра. Это небольшой диагностический
набор из одного листа, без независимой тестовой выборки и без подтверждённого эталона для новой карты.

Подсказки сформированы **из референса автоматически**: одна положительная в глубине целевой области,
две отрицательные в окружающих областях. Это идеализированные подсказки, а не замер работы пользователя.
Подбор параметров по этим четырём результатам не выполнялся.

Первый алгоритм группирует цвета, после чего берётся связная область под положительной точкой.
Он не использует отрицательные точки. Новые методы используют все три точки. Поэтому сравнение
характеризует разные рабочие сценарии и не является строгим сравнением одинаково информированных моделей.
MobileSAM выбирает маску по соблюдению подсказок и собственной оценке, не по совпадению с референсом.

## Метрики

IoU — площадь пересечения результата с референсом, делённая на площадь объединения; 1 — полное совпадение.
F1 границ учитывает допуск 3 рабочих пикселя. Край окна и границы отсутствующих данных исключены
из оценки границ. Это допуск на рабочем растре, а не согласованная геологическая точность в метрах.

| Фрагмент | Первый алгоритм, IoU | Цвет + точки, IoU | MobileSAM, IoU |
|---|---:|---:|---:|
| O2kr1 | 0.551 | 0.944 | 0.584 |
| O2-3mk | 0.461 | 0.439 | 0.500 |
| Cm3il | 0.014 | 0.105 | 0.174 |
| Q_IV | 0.257 | 0.318 | 0.410 |
| Среднее по четырём окнам | 0.321 | 0.452 | 0.417 |

Среднее F1 границ: 0.294 / 0.383 / 0.363 соответственно.
**0.452 не означает «45,2% карт оцифровываются правильно».** Это среднее пространственное
совпадение конкретных выбранных объектов при описанных условиях.

## Время и память

Каждый метод запускался отдельным процессом на текущем Mac ARM64, macOS 27.0.1, Python 3.11.9.
Для OpenCV/PyTorch задано 2 вычислительных потока. Приведены разовые замеры, без гарантии
повторения на другом устройстве. Время не включает показ интерфейса, экспорт и ручную проверку.

| Метод | Время одного окна | Пиковый RSS процесса |
|---|---:|---:|
| Первый алгоритм | 0.093–0.110 с | 187 МиБ |
| Цвет + подсказки | 0.131–0.163 с | 170 МиБ |
| MobileSAM | первый вызов 4.20 с; следующие окна 0.427–0.432 с | 980 МиБ |

Первый вызов MobileSAM включает импорт и загрузку весов; следующие окна используют уже
загруженную модель, но требуют нового кодирования изображения. В приложении закодированное
изображение последней рамки кэшируется для повторных подсказок. RSS относится к одному процессу
исследования, не к суммарной памяти интерфейса и рабочего процесса.
Минимальные требования 8 ГБ ОЗУ и слабый CPU пока не подтверждены испытанием на таком ПК.

## Что показала проверка

- Подавление печатных помех и подсказки хорошо сработали на выбранной зелёной заливке O2kr1.
- Светлые заливки, узкие области и штриховка остаются проблемой обоих подходов.
- MobileSAM не даёт однозначного преимущества и требует больше памяти. Он оставлен необязательным.
- На двух участках новой сложной карты выполнена дополнительная визуальная проверка обоих методов.
  Все четыре результата преобразованы в валидные полигоны и экспортированы. Геологическая
  правильность не подтверждена: в частности, на одном участке оба метода выделили слишком
  небольшой фрагмент. Для новой карты численная точность не заявляется.
- Принятие выделенной области в полную автосегментацию проверяется отдельно от точности распознавания.

## Воспроизведение

Из папки проекта, с установленным пакетом GeoTrace:

```sh
python tools/prepare_reference.py --example "/path/to/Для Жени/Пример" --out "/path/to/work/benchmark"
python tools/benchmark_prompts.py --data "/path/to/work/benchmark" --method baseline
python tools/benchmark_prompts.py --data "/path/to/work/benchmark" --method color
python tools/benchmark_prompts.py --data "/path/to/work/benchmark" --method mobilesam --checkpoint "/path/to/mobile_sam.pt"
```

Для MobileSAM нужны необязательные зависимости из README. На Windows измерение памяти использует
psutil с периодом 10 мс; на macOS/Linux — `ru_maxrss`. Бенчмарк на Windows пока не выполнялся.
