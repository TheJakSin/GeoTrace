# Автоматическое выделение: обычный режим и «Скан»

Это диагностическое сравнение на **одном предоставленном листе**, не общая оценка точности
геологической оцифровки. Геологические названия и легенда не распознаются.

## Данные и фиксированный протокол

Растр: `Пример/Растр/Геологическая карта_clip_cut_buffer800.tif`.
Вектор для сравнения: `Пример/Вектор/gpkg/geolmap_edit.gpkg` (75 непустых объектов).
Сравнение в рабочем разрешении 1600 × 963, 7 цветовых групп, подавление пятен до 80 px,
seed 42, без положительных/отрицательных подсказок. Исходные файлы не изменены.
Вектор используется только для оценки, не подаётся алгоритму выделения.

До просмотра метрик зафиксированы три кандидата: локальная реконструкция цвета из метода
подсказок; морфологическое закрытие RGB 5 × 5; закрытие RGB 3 × 3. Во всех трёх median 5
и вес L=0,4 в Lab. Выбор сделан по четырём ранее изученным **полным** объектам с ID 1, 2, 14, 75:

| Вариант | Среднее IoU на 4 объектах |
|---|---:|
| Прежний алгоритм | 0,451 |
| Локальная реконструкция → «Скан» | **0,591** |
| Закрытие 5 × 5 | 0,473 |
| Закрытие 3 × 3 | 0,375 |

Затем выбранный вариант без донастройки сравнили с прежним на остальных объектах,
занимающих не менее 256 валидных рабочих пикселей: **67 объектов**. Четыре меньших
объекта не входят в эту оценку. Объекты принадлежат тому же листу и не являются
пространственно независимой внешней выборкой.

## Метрики и результат

Для каждого эталонного объекта берётся лучшее IoU **одного связного** выделенного полигона
внутри известного эталонного покрытия: площадь пересечения / площадь объединения.
Слияние нескольких фрагментов ради улучшения оценки не разрешено. Это сопоставление с
эталоном для измерения; приложение само не знает, какой объект эталону соответствует.
Номера цветов сравнивать не нужно. Среднее по объектам невзвешенное.

| Метрика | Обычный | Скан |
|---|---:|---:|
| Среднее IoU, 67 объектов | 0,455 | **0,553** |
| Медианное IoU, 67 объектов | 0,416 | **0,610** |
| Точность границ, весь известный лист | 0,495 | **0,690** |
| Полнота границ, весь известный лист | **0,907** | 0,855 |
| F1 границ, весь известный лист | 0,640 | **0,764** |
| Полигонов без сохранённых ручных правок | 1130 | 324 |
| Один локальный замер сегментации + векторизации | 0,31 с | 0,83 с |

Границы сравниваются на **всём** известном покрытии, включая четыре объекта выбора рецепта;
допуск 3 рабочих пикселя, от рамки/NoData исключена полоса 4 пикселя. Время не включает
чтение исходника, запуск процесса, отрисовку, сохранение и защиту старой геометрии.
Это не обещание скорости на других компьютерах. Меньшее число полигонов само по себе
не означает более правильную геологическую карту.

Улучшились 45 объектов, ухудшились 22, без изменения — 0. Наиболее заметные ухудшения:

| ID эталона | Обычный IoU | Скан IoU |
|---|---:|---:|
| 68 | 0,588 | 0,065 |
| 35 | 0,629 | 0,154 |
| 16 | 0,677 | 0,336 |
| 40 | 0,402 | 0,078 |
| 67 | 0,376 | 0,055 |

Подавление печати уменьшает раздробленность, но может стирать реальные узкие тёмные
области и объединять похожие заливки. Поэтому «Скан» — отдельный экспериментальный
профиль, обычный остаётся выбранным по умолчанию. По этим результатам не меняли параметры
и не выбирали повторно другой рецепт.

## Сохранность работы

На той же карте отдельно проверен пересчёт после ручного смещения общей вершины:
2 изменённых объекта сохранены с точной геометрией, ID и атрибутами. Итог — 766 полигонов:
сохранённые сложные контуры разрезают новые области, поэтому этот результат не равен 324
полигонам при обработке с нуля. Разность покрытий около 3,9 × 10⁻¹⁵, сумма площадей минус
площадь объединения около 3,1 × 10⁻¹⁶ в квадратных единицах исходных координат.
Это погрешность вычислений, не показатель геологической точности. Проверены применение,
сохранение/чтение проекта и отмена до исходных 1130 объектов.

## Воспроизведение

Подготовить `data.npz` существующим `tools/prepare_reference.py`, затем:

```sh
python tools/benchmark_auto.py --data /path/to/data.npz --output /path/to/report
```

Скрипт сравнивает итоговые реализации baseline/scan без поиска параметров и сохраняет
`auto-metrics.json` с оценками каждого объекта и две PNG-заливки. Проверка по итоговому коду
полностью воспроизвела IoU первоначального эксперимента. Рабочие материалы сравнения
в текущей поставке лежат рядом с проектом в `GeoTrace-auto-evaluation/`.
